## Bugs found and how they were caught

1. **SARIMA silently never fit (scipy incompatibility).** `scipy` was unpinned,
   so pip installed 1.18.1, which dropped the `disp` kwarg that `statsmodels`
   0.14.4 passes; every SARIMA fit raised and fell back to the baseline. Caught
   by explicitly checking that SARIMA produces forecasts different from the
   seasonal-naive value (not just that tests passed). Fixed by pinning
   `scipy==1.14.1`.
2. **Monitoring mixed forecasting methods (look-ahead).** The monitor was handed
   the full multi-method backtest frame; after sorting, same-month rows from
   different methods interleaved, so a month's "trailing" error window could
   include another method's error for that same month. Caught in independent
   review by constructing a two-method frame. Fixed: filter to the single best
   method before monitoring; the monitor now raises on a duplicate-month index.
3. **`eval_months=0` evaluated the whole series.** `series.index[-0:]` returns
   everything. Caught in review. Fixed with validation (`eval_months >= 1`,
   `min_train_months >= 1`) and exact slicing.
4. **SARIMA fallback didn't match the plan.** Code fell back to seasonal-naive
   (M1); the plan specifies seasonal-naive-plus-trend (M2). Caught in review
   against `docs/PLAN.md`. Fixed to fall back to M2, then to M1 only if the
   series is too short for the trend window.
5. **The SARIMA real-fit test was too weak.** On a noise-free series the fitted
   forecast equals the M2 fallback, so the test passed even when SARIMA never
   fit. Caught in review via a mutation (forcing a fallback still passed). Fixed
   to use a deterministic noisy series (asserting the fit diverges from M2) plus
   a `caplog` assertion that no fallback warning was logged; re-mutation-tested
   to confirm it now fails on a silent fallback.
6. **Makefile `backtest`/`monitor` crashed.** They ran `src/backtest.py` as a
   script, but the modules use `from src.config import ...`, giving
   `ModuleNotFoundError`. Caught by running the targets. Fixed to
   `-m src.backtest` / `-m src.monitoring`.
7. **Makefile `setup` assumed a modern `python3`.** System `python3` here is
   3.8.10 (<3.11), which would fail the numpy/pandas install and could clobber
   the venv. Caught in review. Fixed with `PYTHON_BOOTSTRAP ?= python3.12` and a
   guard that fails clearly if the interpreter is older than 3.11.
8. **statsmodels "No frequency information" warning.** The processed-CSV load
   didn't set a monthly frequency. Fixed with `.asfreq("MS")` in
   `backtest.main()`.

Additional robustness added during review: duplicate-month index checks in the
backtest and monitor, `window >= 2` / `threshold_sigma > 0` validation, and a
SARIMA minimum-length guard (≥ 2× the seasonal period) before fitting.
